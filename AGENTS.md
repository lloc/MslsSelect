# Repository Guidelines

## Project Structure & Module Organization
- `MslsSelect.php` bootstraps the plugin and stays the single PHP entry point.
- `js/mslsselect.js` (with the minified twin) powers the UI; update both when tweaking frontend behavior.
- `tests/` houses the PHPUnit specs plus two separate bootstraps — see Testing below.
- `bin/` contains contributor utilities (`git-release.sh`, githooks); call these scripts instead of duplicating logic.
- `mslsselect/` and `mslsselect.zip` are build output, regenerated by `composer build`. Never edit or commit them.

## Build, Test, and Development Commands
- `composer install` installs PHP tooling; rerun after dependency bumps or fresh clones.
- `composer qa` runs the full gate: `phpcs`, `phpstan`, then `phpunit`. This is what CI runs.
- `composer phpcs` checks the WordPress coding standards and PHP 7.4 compatibility via `.phpcs.xml.dist`; `composer phpcbf` fixes what can be fixed automatically.
- `composer phpstan` runs PHPStan (level 6) against `MslsSelect.php`; keep it passing before pushing.
- `composer phpunit` executes the PHPUnit suite; `composer phpunit:html` writes HTML coverage to `coverage/` (requires Xdebug).
- `composer githooks` copies the pre-commit hook into `.git/hooks/`.
- `composer build` invokes `bin/git-release.sh` and refreshes the distributable.

The dev tree requires PHP 8.0+ because Multisite Language Switcher 3.0 depends on `php-di ^7`.
The plugin itself still targets PHP 7.4, which `PHPCompatibilityWP` verifies statically.

## Coding Style & Naming Conventions
- Follow WordPress PHP style: tabs for indentation, PascalCase classes.
- Run `composer phpcs` before committing; `.phpcs.xml.dist` covers `MslsSelect.php` and `tests/`.
- Mirror the spacing and semicolon usage already present in `js/mslsselect.js` for JavaScript updates.

## Testing Guidelines
- Name PHPUnit classes `*Test.php` and mirror the class they cover.
- Use Brain Monkey helpers for WordPress hooks instead of creating globals manually.
- `tests/bootstrap.php` defines `ABSPATH` and requires the plugin file. Do **not** load the plugin
  through composer's `autoload-dev` instead: `MslsSelect.php` exits without `ABSPATH`, and the
  autoloader gives you no place to define it.
- `tests/phpstan-bootstrap.php` is deliberately a different file. It loads the **real** Multisite
  Language Switcher from `vendor/` so that static analysis validates the MSLS symbols MslsSelect
  documents. Never bootstrap PHPStan from test doubles — stubs report whatever they were written
  to report and hide API changes rather than catching them. To prove the analysis is real, rename
  `$link->txt` to something wrong and confirm PHPStan fails.
- Prefer regression cases that assert rendered HTML or hook behavior, and assert the branch that
  actually matters — a fixture with a mistyped property silently exercises the miss branch while
  looking like it covers the hit branch.

## MSLS Integration Notes
- MslsSelect talks to MSLS through hooks only: `msls_output_get_tags`, `msls_output_get`, and the
  `option_msls` / `default_option_msls` option filters. It references no `lloc\Msls\*` class.
- Because of that there is **no** runtime MSLS version gate, and none should be added without a
  reason: gating would disable working MSLS 2.x installs for no benefit.
- Both option filters are required. `get_option()` applies `option_{$option}` only when the option
  row exists and falls back to `default_option_{$option}` when it does not — the state of a fresh
  MSLS install.

## Commit & Pull Request Guidelines
- Write concise, imperative commit subjects (`Add select placeholder`) and reference issues in the body (`Refs #123`) when relevant.
- Summarize scope, manual testing, and screenshots (for UI changes) in every PR.
- Confirm local parity with CI by running `composer install` and `composer qa` prior to review.

## Release & Packaging Notes
- Bump the version in **three** places to the same value: the plugin header in `MslsSelect.php`,
  `MslsSelect::VERSION`, and the `Stable tag` in `readme.txt`; then add the matching `= x.y.z =`
  changelog entry and an `== Upgrade Notice ==` block. WordPress.org rejects the release if header
  and stable tag disagree. A test asserts that header and constant agree.
- The changelog must describe what actually changed. A release that only claims alignment with a
  new MSLS version, without carrying the corresponding work, has to be retracted.
- Run `composer build` locally only to inspect the result. The shipped artifact is built in CI:
  `.github/workflows/deploy.yml` runs the same `composer build`, verifies the contents and deploys
  them through `BUILD_DIR: mslsselect`. Without that `BUILD_DIR` the 10up action rsyncs the whole
  workspace instead — a different artifact than the one Plugin Check verified.
- Keep the build verification honest: check for files this plugin actually ships. MslsSelect has no
  `languages/` directory, so a translation check there would be a check for files that never existed.
- Tag without a `v` prefix (`3.0.0`) and push the tag — that push is what triggers the deploy workflow.
